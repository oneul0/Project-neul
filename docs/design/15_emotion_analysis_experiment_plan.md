# 감정 분석 고도화 실험 계획

작성일: 2026-04-01

## 1. 문제 재정의

이 실험의 목표는 "감정 분류 정확도를 높이는 것" 자체가 아닙니다.

현재 더 중요한 목표는:

- 스트리머가 긴 다시보기에서 편집 후보 구간을 빠르게 찾을 수 있게 돕기
- 방송 흐름이 바뀌는 지점을 쉽게 찾게 하기
- 왜 이 구간이 추천됐는지 납득 가능한 설명을 제공하기

즉 결과물은 감정 분류기보다 "편집 보조 도구"에 가깝습니다.

## 2. 현재 실험 방향

### 내부 점수 축

- `intensityScore`
  - 얼마나 반응이 몰렸는지
- `transitionScore`
  - 직전 구간 대비 흐름이 얼마나 바뀌었는지
- `editabilityScore`
  - 실제 편집 포인트로 쓰기 얼마나 좋은지
- `reactionLabel`
  - 웃음, 놀람, 고조, 긴장 같은 반응 유형

### 사용자 노출 방식

사용자에게는 내부 점수명을 그대로 보여주지 않습니다.

현재 UI 기준:

- `추천 강도`
- `추천 이유`
- `대표 채팅`

즉 내부 점수는 분석 로직용, 사용자 화면은 해석 가능한 표현 중심입니다.

## 3. 현재 구현된 방향

- 단일 하이라이트 점수만 저장하지 않고 편집 관점 점수 분리
- 시간대 버킷 기반 하이라이트 분산 선택
- 조용하다가 갑자기 채팅이 붙는 구간에 가중치 부여
- 추천 이유를 자연어 문장으로 생성

## 4. 아직 더 실험할 것

- reaction label이 실제 편집 톤으로 유의미한지
- 추천 이유 문구가 사람에게 납득되는지
- intensity / transition 가중치 조합이 적절한지
- 조용한 방송에서도 후보 구간이 너무 빈약하지 않은지

## 5. 성공 기준

- 하이라이트가 특정 시간대에만 몰리지 않는다
- 후반부에도 의미 있는 구간이 살아남는다
- 대표 채팅이 대부분 비어 있지 않다
- 스트리머가 "왜 이 구간을 먼저 보라고 하는지" 바로 이해한다
