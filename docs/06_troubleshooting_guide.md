# 🛠️ 트러블슈팅 및 심화 구현 가이드

이 문서는 프로젝트 개발 과정에서 발생한 주요 문제들과 그 해결책, 그리고 핵심 로직의 심화 구현 내용을 체계적으로 정리합니다. 나중에 유사한 문제가 발생하거나 기능을 확장할 때 참고할 수 있습니다.

---

## 1. LLM 응답 역직렬화 (JSON Parsing) 이슈

### 🚨 문제 상황
Ollama와 같은 로컬 LLM은 프롬프트의 지시사항을 완벽히 따르지 않을 때가 있습니다. 특히 "JSON 배열로만 응답하라"고 해도 기분에 따라 단일 JSON 객체(`{...}`)를 보내거나, 텍스트 설명을 섞어 보낼 때가 있어 `ObjectMapper`가 에러를 냅니다.

### ✅ 해결책: 유연한 파싱 로직 (`OllamaAnalyzerService.java`)
1. **정규식/인덱스 기반 추출**: 응답에서 처음 등장하는 `[`와 마지막 `]` 사이의 텍스트만 추출합니다.
2. **타입 분기 처리**: 추출된 문자열이 `{`로 시작하면 단일 객체로, `[`로 시작하면 리스트로 역직렬화하도록 로직을 보강했습니다.
3. **Fallback 보장**: 어떤 이유로든 파싱에 실패하면 해당 배치를 모두 `NEUTRAL`로 처리하여 파이프라인이 멈추지 않게 합니다.

## 2. Kafka Type Id 헤더 충돌

### 🚨 문제 상황
Spring Kafka의 `JsonSerializer`는 기본적으로 메시지 헤더에 송신자 측의 클래스 패스(`__TypeId__`)를 포함합니다. 수신자 측(`core-api`)에 동일한 패키지의 클래스가 없으면 `ClassNotFoundException`이 발생하며 메시지 소비가 중단됩니다.

### ✅ 해결책: 타입 정보 비활성화 및 기본 타입 지정
- **Producer (Analyzer)**: `ADD_TYPE_INFO_HEADERS` 옵션을 `false`로 설정하여 헤더를 제거합니다.
- **Consumer (Core-API)**: `VALUE_DEFAULT_TYPE`을 수신측의 DTO 클래스로 강제 지정하여 헤더 없이도 역직렬화가 가능하게 합니다.

---

## 3. R2DBC 엔티티와 DB 스키마 불일치

### 🚨 문제 상황
`AnalyzedChat.java` 엔티티에 새 컬럼(`emotion_type` 등)을 추가했는데, 기존 DB 테이블(`analyzed_chats`)에 해당 컬럼이 없으면 저장 시 SQL 에러가 발생합니다. Spring Data R2DBC는 스키마 자동 변경(ddl-auto) 기능이 없거나 제한적입니다.

### ✅ 해결책: 수동 스키마 관리 및 초기화
- `backend/core-api/src/main/resources/schema.sql`을 항상 최신으로 유지합니다.
- **개발 환경 초기화**: 스키마 변경 시 `docker-compose down -v` 명령어로 볼륨을 완전히 삭제한 후 다시 `up` 하여 `schema.sql`이 다시 실행되게 합니다.

## 4. 실시간 하이라이트 감지 (Spike Detection)

### ⚙️ 구현 메커니즘
1. **감정 임계값**: `NEUTRAL`이 아닌 감정의 `score`가 **0.8(80%)** 이상이면 잠재적 하이라이트로 판단합니다.
2. **중복 방지 (Cooldown)**: 동일한 채널에서 **10초 이내**에 발생한 하이라이트는 스킵하여 알림 폭주를 막습니다.
3. **실시간 썸네일**: 하이라이트 발생 즉시 치지직의 `live-status` API를 호출하여 현재 방송의 실시간 이미지 URL을 캡처하고, 이를 SSE로 클라이언트에 전송합니다.

---

## 5. 고속 배칭(Batching) 튜닝

### 📊 성능 최적화 전략
- **기존 (1분)**: 분석 주기가 너무 길어 실시간성이 떨어짐.
- **현재 (2초/50개)**: 2초 단위로 윈도우를 나누거나, 메시지가 50개가 쌓이면 즉시 분석 서버로 전송합니다.
- **결과**: LLM의 분석 부하를 최소화하면서도 사용자에게는 마치 실시간으로 분석이 일어나는 듯한(2초 지연) 경험을 제공합니다.

---

## 6. 클라이언트 사이드 스냅샷 저장

### 💾 설계 의도
서버의 저장 공간과 트래픽 부담을 줄이기 위해, 하이라이트 이미지를 서버에 미리 저장하지 않습니다. 대신 클라이언트 대시보드의 타임라인에서 사용자가 직접 **[💾 Save Image]** 버튼을 누를 때만 브라우저가 직접 Chzzk URL을 통해 이미지를 다운로드하도록 구현했습니다.
