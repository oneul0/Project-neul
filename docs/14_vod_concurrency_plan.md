# VOD 동시성 및 안전성 계획

작성일: 2026-03-31
최종 업데이트: 2026-04-01

## 1. 현재 상태

현재 VOD 분석은 다음 구조로 동작합니다.

- 사용자가 `분석 시작`을 누르면 HTTP 요청은 바로 끝남
- 실제 VOD 크롤링/분석은 백그라운드 비동기 작업으로 진행
- 서로 다른 VOD 작업은 동시에 실행될 수 있음
- 한 VOD 내부의 채팅 청크 수집은 순차적으로 진행

즉 "작업 간 병렬, 작업 내부는 순차" 구조입니다.

## 2. 왜 제한이 필요한가

지금은 아래 제한이 아직 없습니다.

- 사용자별 동시 분석 제한
- 시스템 전체 동시 분석 제한
- 큐 정책

그래서 동시 사용자가 많아지면:

- collector outbound 요청 증가
- analyzer 메모리 사용량 증가
- Kafka 적체
- DB 저장 지연

같은 문제가 생길 수 있습니다.

## 3. 먼저 측정할 것

- VOD 1건당 평균 처리 시간
- pagesProcessed / chatsCollected 평균
- collector 응답 지연
- analyzer 메모리 사용량
- Kafka lag
- 1건, 2건, 3건, 5건 동시 실행 시 처리 시간 변화

## 4. 초기 가설

실측 전 보수적인 시작점:

- 사용자당 동시 VOD 분석 1건
- 시스템 전체 동시 VOD 분석 2~3건

## 5. 구현 방향

### 사용자별 제한

- owner channel id 기준 실행 중 작업 수 추적
- 이미 진행 중이면 새 요청 거절 또는 대기열 등록

### 시스템 전체 제한

- collector에서 전역 실행 중 작업 수 추적
- 최대치를 넘기면 거절 또는 큐 처리

### 상태 모델 확장 후보

현재 상태:

- `IDLE`
- `REQUESTED`
- `CRAWLING`
- `ANALYZING`
- `COMPLETED`
- `FAILED`

추가 후보:

- `QUEUED`
- `REJECTED_LIMIT`

## 6. UI 반영 방향

- 지금 실행 중인지
- 대기 중인지
- 제한 때문에 시작이 안 되었는지
- 동일 사용자의 다른 분석 작업 때문에 막힌 것인지

를 명확히 보여줘야 합니다.

## 7. 적용 전 체크리스트

- 동시 1건 정상 동작 확인
- 동시 2건 이상에서 처리 시간과 메모리 변화를 측정
- 상태가 stuck 되지 않는지 확인
- 실패 작업이 끝난 뒤 슬롯이 정상 반납되는지 확인
